# aihappey-ai

A multi-provider **.NET AI gateway** exposing normalized endpoints for models, media, skills, agents and MCP capabilities.

No smart routing fairy. No shiny admin portal. No hidden logic maze. No code execution.
Just provider capabilities flattened, normalized hard and exposed through open contracts.
Stateless. Boring on purpose.

Access 150k+ models and provider-native capabilities from your favorite client.

**Documentation:** https://docs.aihappey.com/gateway  
**API:** https://ai.aihappey.net

## Quick start

```bash
curl "https://ai.aihappey.net/v1/chat/completions" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $OPENAI_API_KEY" \
  -d '{
    "model": "openai/gpt-5.4-mini",
    "messages": [
      { "role": "user", "content": "Say hi" }
    ]
  }'
```

See the [API documentation](https://docs.aihappey.com/gateway) for endpoints, authentication, request schemas and examples.

## Run standalone on Windows

Run the gateway standalone on your own Windows machine. Download the latest standalone Windows x64 build:
[aihappey-windows-x64.zip](https://github.com/achappey/aihappey-ai/releases/download/latest/aihappey-windows-x64.zip)

Provider credentials are loaded from: `%LOCALAPPDATA%\aihappey\headers.json`  
Example: `{"X-OpenAI-Key":"sk-...","X-Anthropic-Key":"sk-ant-..."}`

Start `aihappey.Windows.exe` and use the same APIs locally at `http://localhost:5000`.

## Provider Support Matrix

Below is a capability matrix for all supported providers. 
Provider descriptions and links are available [here](https://chat.aihappey.com/providers).

The table below shows which endpoints each provider implements (✅), not yet implemented (❌), partially implemented (🟡) or for which an endpoint is not applicable to the provider (➖).

RampRouter Decisions uses the existing `/v1/decisions` and `/api/decisions` gateway endpoints and Router credentials/model discovery. Availability depends on the account's `router.surfaces` in `/v1/models`. Predicate, choice, and score questions are supported for GPT-6 Luna and Jev; inline images are supported only for OpenAI models. Metadata, `stream: false`, and `service_tier: auto/default` can be supplied as native request fields or under `providerOptions.ramprouter`. Fallback lists cannot be combined with the contracts' required single model; streaming, flex/pinned non-default tiers, routing strategies, and unknown options are rejected explicitly. Jev requires unique question names. Missing token totals are calculated from input/output usage; omitted confidence defaults to zero with a warning, not an inferred confidence. SDK responses retain the original upstream body and headers. No System One gateway endpoint is added.

DigitalOcean Decisions uses the existing `/api/decisions` and `/v1/decisions` gateway endpoints and DigitalOcean model access key/model discovery, posting upstream to `/v1/systemone` (for example, model `digitalocean/typesafe-jev-1.13.0`). Choice, score (text levels or objects with a `label`), and boolean (`noul`) questions can be combined in one request. Typed state accepts text, JSON objects, or arrays of text; SDK text/JSON parts and inline text files are adapted through the existing SDK mapper. OpenAI text messages are preserved as structured JSON evidence; question order/names and string-versus-boolean choice values are retained. Scores use zero-based level positions; unreported OpenAI token-detail counters default to zero with a warning. Typed instructions and choice descriptions must be text; boolean criteria, box questions, images/audio/video, streaming, reasoning, output-token controls, provider options, safety identifiers, and additional OpenAI fields are explicitly unsupported. Native confidence, score legends, and usage remain in provider metadata; typed responses also retain the original response body/headers. Jev's 64K total-token and 32K state-plus-longest-question limits are enforced upstream (no approximate local tokenizer); limit, subscription-tier, and other upstream errors retain their HTTP status and body. Jev requires a qualifying subscription tier. No gateway endpoint or contract is added. See the [System One documentation](https://docs.digitalocean.com/products/inference/how-to/use-system-one-api/).

OpenCodeZen Decisions uses the existing `/api/decisions` and `/v1/decisions` gateway endpoints and OpenCodeZen credentials, posting to `https://opencode.ai/inference/systemone/v1/systemone` with `jev-1.13` or `jev-1.13-free`. It supports combined `noul`, choice (2–52 options), and score (2–10 levels) questions with a shared state. Text and JSON state are supported; OpenAI text input is preserved as structured evidence and string/boolean choice values and score labels are retained. Noul criteria, box questions, non-text instructions, images, streaming, reasoning, output-token controls, provider options, safety identifiers, and additional OpenAI fields are rejected explicitly. Native usage, confidence, legends, response headers, and body are retained; OpenAI-compatible token-detail counters default to zero with a warning. Upstream errors preserve their HTTP status and body. Decision models are cataloged as `decision`. See the [OpenCode Console models documentation](https://opencode.ai/v2/docs/console/models/).

Alibaba Decisions uses the existing `/api/decisions` and `/v1/decisions` endpoints and Alibaba API key/model discovery, posting to `compatible-mode/v1/systemone` with model `decision-model-preview`. It supports text or structured JSON state, up to 16 combined `noul`, choice, and score questions (choice options and score levels are limited to 255); score levels use zero-based probability-weighted positions. Confidence, distributions, score legends, request IDs, and upstream usage are retained in provider metadata and the original response. OpenAI text messages are preserved as structured evidence; inline images, additional OpenAI fields, safety identifiers, and nonempty provider options are rejected. Only `input_tokens` is reported upstream; OpenAI-compatible output-token usage is zero. No gateway endpoint or contract is added. See the [Alibaba Decision Model API documentation](https://www.alibabacloud.com/help/en/model-studio/decision-model-api).

InceptionLabs Decisions uses the existing `/api/decisions` and `/v1/decisions` endpoints, API key, and catalog discovery with `inceptionlabs/mercury-decide`. Boolean (`noul`), choice (1-255 options), and score (1-10 ordered levels) questions share text or structured JSON state. Typed instructions are optional; structured instructions/criteria and explicit null choice/boolean descriptions are preserved. SDK text, JSON, inline text files, and inline images use the existing state mapper. Images may appear anywhere in state or instructions, never criteria: base64 PNG/JPEG/WebP/GIF only, at most 10 MiB each and 16 per request; the serialized request is limited to the upstream default 20 MiB. Remote images, audio/video/binary files, box questions, image-detail controls other than the default `auto`, streaming, reasoning, output-token controls, safety identifiers, additional OpenAI fields, and nonempty provider options are explicitly rejected. Extraction is limited to selecting/scoring supplied candidates through existing question types; free-form extraction has no representation in the current contracts. Scores are zero-based weighted positions; OpenAI question order/names and string-versus-boolean choices are retained. Native confidence, legends, usage, body, and headers remain in typed response metadata; unreported OpenAI token-detail counters default to zero with a warning. Upstream errors retain HTTP status and body. See the official [Decisions guide](https://docs.inceptionlabs.ai/capabilities/decisions) and [API reference](https://docs.inceptionlabs.ai/api-reference/decisions/create-a-decision).
